# Freeze complete Run Manifests and do not replace failed slots

Every certification batch has an immutable Run Manifest that hashes the Provider Profile, Runtime and code, System Prompt, Skill, MCP Schemas, Knowledge Snapshot, Action Cards, Safety rules, vision pipeline, Evidence Packets, Broker labels, Gold, permissions, hooks, budgets, timeouts and Generic/FixAgent configurations. Any change starts a new batch; results from different manifests are never merged. Each Case and configuration has exactly three pre-numbered Run Slots, with at most the already defined single recovery inside each Run. `SYSTEM_ERROR` occupies its slot and is not replaced. Two matching valid results are required for a Case-level Outcome; otherwise the evaluation status is `INCONCLUSIVE`. An inconclusive side cannot produce Win/Loss/Tie, and all five Cases must be comparable before the relative-effect gate or `PRODUCT_GO` can pass.
