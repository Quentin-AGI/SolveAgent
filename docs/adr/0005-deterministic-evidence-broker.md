# Replay historical Cases through a deterministic Evidence Broker

Automated Case replay uses an evaluation-only Evidence Broker shared by Generic Agent and FixAgent. Every authentic historical reply is split into minimal verbatim Evidence Atoms and pre-labelled with controlled fact types; the Agent requests one or more `requested_fact` values and explains why, and the Broker performs exact matching only, returning the corresponding Atoms or `EVIDENCE_UNAVAILABLE` per item. Both configurations receive the same minimal instruction that new historical facts must be requested through the Broker. A natural-language question without the tool call becomes `UNFULFILLED_REQUEST`: no evidence is released and the round counts toward customer cost. For action outcomes and recovery confirmation, the data owner freezes acceptable Action IDs, versions, parameter ranges, prerequisites and result Atoms. The Broker releases them only after the Agent has actually published a matching action; an alternative action receives `EVIDENCE_UNAVAILABLE` and cannot borrow another action's historical success. The Broker never uses semantic similarity, supplies a missing call, selects a diagnostic step or fabricates a user response. The data owner freezes packets, Gold Outcomes, cutoffs and hashes, while the Runtime owner remains blind to Gold and future evidence until scoring; this avoids a second simulation Agent and reduces answer leakage.
