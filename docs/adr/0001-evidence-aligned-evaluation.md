# Use evidence-aligned cases and a knowledge-matched baseline

FixAgent V0 keeps a five-Case minimum: three `REPLAYABLE + SELF_SERVICE_ELIGIBLE` Cases, one `REPLAYABLE + EXPERT_HANDOFF` Case, and one `REPLAY_BLOCKED + EXPERT_HANDOFF` Case. Replayability is frozen by the data owner before the first run and cannot be changed by an Agent request; unavailable facts in a `REPLAYABLE` Case remain `EVIDENCE_UNAVAILABLE` and affect the run rather than removing the Case from the denominator. All five are scored for Appropriate Outcome, but only the three self-service Cases enter the resolution-rate denominator; the replay-blocked Case tests whether the Agent recognises missing evidence and stops correctly. Every Case freezes its Target Symptoms, pre-existing non-target symptoms and verification method before the first run. `RESOLVED` requires explicit user confirmation for every Target Symptom; partial improvement, thanks, silence, session exit or Agent inference do not qualify, and replay uses only a frozen `resolution_confirmation` Evidence Atom. Any action-induced new fault makes the result `FAIL`. Visual observations cite Evidence Refs, product facts and actions cite versioned Knowledge, and hypotheses remain labelled with supporting evidence; an uncited device action is invalid and an uncited key diagnostic fact is an Evidence Constraint Failure. Generic Agent receives the same approved Knowledge Snapshot, Action Card library and Evidence Broker as FixAgent, so the comparison measures FixAgent's troubleshooting method, Case continuity and evidence discipline instead of merely comparing an informed Agent with an uninformed one. Certification workload is reported per provider as 10 compatibility checks, 30 core Case runs and 18 safety runs; `PRODUCT_GO` needs at least one provider's 58 checks, while `FOUR_PROVIDER_GO` requires all four providers and 232 checks. Each batch uses one Frozen Provider Profile and is invalidated by automatic model or provider fallback, alias remapping or runtime-version changes. When the data gate is `DATA_NO_GO`, Architecture Validation and Dry Runs may proceed only with `NON-SCORED · DATA_NO_GO` displayed on every page, report and screenshot region; resolution, comparison and Product Go values remain `N/A`.
