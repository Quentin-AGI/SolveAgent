# Persist explicit MCP state in a per-Case file event store

FixAgent may answer naturally, but application state changes only through explicit MCP calls such as `update_case_state`, `record_action_result` and `create_handoff`; the application never parses model prose with regexes or another model to infer Route, Outcome or evidence. Action results use `COMPLETED`, `DECLINED`, `UNABLE_TO_PERFORM` or `RESULT_UNKNOWN`; refusal is not model failure or resolution. V0 stores each Case in an isolated, Schema-versioned directory with atomically replaced `state.json`, append-only `events.jsonl`, redacted `evidence/`, writable `scratch/` and JSON Handoff packets. Each Case permits one active Worker Lease, and every state, action or Handoff write checks `case_id`, `expected_revision` and `idempotency_key`; duplicates return their original result, while revision conflicts stop the Run instead of overwriting state or creating another Handoff. `HANDOFF_CREATED` is visible only after atomic Outbox persistence. A normal persistence failure becomes `SYSTEM_ERROR`; a Safety failure still shows the fixed stop message and raises a critical operational event without claiming a handoff exists. This keeps the demo inspectable and auditable without introducing a database or a hidden Workflow Engine.
